# 39. Step 33 위치 주소 표시와 검색 실행 방식 정리

## 목표

사용자에게 좌표 숫자 대신 읽을 수 있는 주소를 보여주고, 검색도 글자 입력마다 바로 실행되지 않도록 정리합니다.

또한 공고 등록 화면에서는 큰 주소를 직접 길게 입력하지 않고, `현재 위치 불러오기`로 기본 주소를 채운 뒤 필요한 경우에만 `1층 102호` 같은 추가 상세주소를 적도록 흐름을 바꿉니다.

이번 단계에서는:

- 메인 화면 현재 위치를 주소 문자열 중심으로 표시
- 공고 등록 위치 확인 메시지에서 좌표 제거
- 공고 등록 위치를 `현재 위치 불러오기 + 추가 상세주소` 흐름으로 변경
- 메인 화면 검색을 `검색 버튼` 또는 `엔터` 실행 방식으로 변경
- 내 공고 관리 검색도 `검색 버튼` 또는 `엔터` 실행 방식으로 변경

까지 반영했습니다.

## 1. 위치는 좌표보다 주소 우선

이전에는 reverse geocoding 결과를 못 쓸 때 `위도 37.xxx, 경도 127.xxx`처럼 숫자가 노출될 수 있었습니다.

이번에는 공통 helper를 만들어서:

- 가능한 경우 `수원시 영통구 매탄동 202-1` 같은 주소 형태
- 주소를 못 만들면 `주소를 확인하지 못했어요`

처럼 보이게 바꿨습니다.

## 2. 공고 등록 위치 확인 메시지 정리

공고 등록/수정 화면에서도 위치 확인 완료 후 좌표를 그대로 보여주지 않게 바꿨습니다.

이제는:

- 공개 위치
- 상세 위치

두 텍스트만 보여주고, 숫자 좌표는 내부 저장용으로만 씁니다.

## 3. 공고 등록 위치를 현재 위치 중심으로 정리

이제 공고 등록/수정 화면에는 긴 주소 입력창 대신 `기본 주소` 미리보기 영역이 보입니다.

사용 흐름:

```text
현재 위치 불러오기
-> 주소 문자열 확인
-> 기본 주소 자동 채움
-> 필요하면 추가 상세주소 입력
```

사용자가 직접 적는 입력칸은 `추가 상세주소`만 남겼습니다.

예:

- `1층 102호`
- `뒷문 옆`
- `엘리베이터 내려서 오른쪽`

즉, 큰 주소는 시스템이 잡고, 사람이 꼭 써야 하는 안내만 추가합니다.

저장 방식은 이렇게 정리했습니다.

- `예약 후 상세 위치 안내`: 기본 주소를 요약해서 공개 위치로 저장
- `처음부터 상세 위치 공개`: 기본 주소 + 추가 상세주소를 합쳐 저장

## 4. 검색은 입력 즉시 말고, 실행할 때만

이전에는 `onChangeText`로 검색 state를 바로 바꿔서 한 글자 입력할 때마다 결과가 다시 계산됐습니다.

이번에는 검색을 두 단계로 나눴습니다.

- `searchInput`: 지금 입력 중인 글자
- `query` 또는 `searchQuery`: 실제 적용된 검색어

즉, 검색 버튼을 누르거나 키보드에서 엔터를 쳤을 때만 목록이 바뀝니다.

## React 개발자 기준으로 보면

- 웹 React에서도 input value와 submitted query를 분리하는 패턴과 같습니다.
- `draft state`와 `applied state`를 나누면, 사용자가 입력 중일 때 리스트가 흔들리지 않아서 UX가 더 안정적입니다.
- 웹 폼에서도 `주소 검색 결과`와 `상세주소 직접 입력`을 분리하는 패턴과 같습니다.
- 이번 구조는 사용자가 매번 긴 주소를 다시 치지 않아도 되게 해서 입력 실수를 줄이는 쪽에 가깝습니다.

## 핵심 코드

```ts
const [searchInput, setSearchInput] = useState('');
const [query, setQuery] = useState('');

const handleApplySearch = () => {
  setQuery(searchInput.trim());
};
```

입력 상태와 실제 검색 상태를 분리해서, 엔터나 버튼 클릭 때만 검색을 적용했습니다.

공고 등록 위치 저장에서는 아래처럼 기본 주소와 추가 상세주소를 합쳐 기존 데이터 구조와 맞췄습니다.
