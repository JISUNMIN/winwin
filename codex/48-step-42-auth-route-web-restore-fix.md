# 48. Step 42 웹에서 `/auth` 복귀 화면 밀림 수정

## 목표

실제 auth 화면을 붙인 뒤 웹에서 주소창으로 `/auth`에 직접 들어가면,
1~2초 뒤 마지막 저장 화면으로 다시 돌아가는 문제가 있었습니다.

이번 단계에서는:

- `/auth` 직접 진입 시 화면을 그대로 유지
- 마지막 경로 자동 복원은 홈(`/`)에서만 실행

하도록 정리했습니다.

## 수정한 파일

```text
src/auth/auth-route-persistence.tsx
```

## 원인

기존 마지막 경로 복원 로직은 앱 시작 시:

```text
/ 또는 /auth 에서 시작
-> 저장된 마지막 경로가 있으면
-> 그 화면으로 replace
```

처럼 동작했습니다.

이 정책은 mock auth 시절에는 크게 문제되지 않았지만,
이제 `/auth`가 실제 로그인/회원가입 화면이 되면서 웹에서 주소창으로 직접 들어간 경우에도
자동 복원이 실행되어 버렸습니다.

즉:

```text
사용자는 /auth를 열고 싶었는데
복원 로직은 "이전 화면으로 돌아가야 한다"고 판단
```

한 것이었습니다.

## 바꾼 점

이제 자동 복원 시작점은 `/auth`가 아니라 `/`만 사용합니다.

즉:

```text
앱이 / 에서 시작하면 마지막 경로 복원 가능
/auth 에 직접 들어가면 그대로 auth 화면 유지
```

정책으로 바꿨습니다.

## 지금 동작 기준

### 웹에서 `/auth` 주소 직접 입력

이제는:

```text
/auth 진입
-> auth 화면 유지
-> 사용자가 직접 로그인/회원가입 가능
```

### 앱을 일반적으로 다시 열기

여전히:

```text
/ 에서 시작
-> 저장된 마지막 경로 확인
-> 현재 역할로 접근 가능하면 마지막 화면 복원
```

흐름은 유지됩니다.

즉 마지막 화면 복원 기능을 없앤 것이 아니라,
`/auth`를 강제로 복원 대상 시작점에서 제외한 것입니다.

## React 개발자 기준으로 보면

이번 수정은 웹에서:

- 앱 시작 루트에서는 last-route restore를 허용하되
- 로그인 페이지(`/auth`)는 명시적 진입 화면으로 취급해서
- 자동 redirect 대상에서 제외

하는 패턴과 비슷합니다.

즉 느낌상:

- `/` = 복원 시작점
- `/auth` = 사용자가 의도적으로 연 화면

으로 역할을 분리한 것입니다.

## 핵심 코드

```ts
function shouldRestoreFromPath(pathname: string) {
  return pathname === '/';
}
```

이제 마지막 경로 자동 복원은 홈에서만 실행됩니다.
