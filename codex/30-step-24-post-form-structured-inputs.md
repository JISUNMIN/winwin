# 30. Step 24 공고 등록 구조화 입력

## 목표

공고 등록 화면의 두 입력을 더 실제 서비스답게 바꿉니다.

- 날짜 입력을 달력 기반 다중 선택 UI로 변경
- 지원 조건 입력을 칩 형태 UI로 변경

그리고 둘 다 최소 1개 이상 없으면 등록할 수 없도록 바꿉니다.

추가로 위치는 나중 지도 API를 붙이기 쉽게:

- 상세 위치
- 공개 방식

으로 나눠 받도록 정리했습니다.

## 수정한 파일

```text
src/app/shop/post/new.tsx
src/app/shop/post/created.tsx
src/data/matchings.ts
```

## 1. 날짜 선택 UI 변경

기존에는 날짜를 쉼표로 직접 입력했습니다.

이번에는 달력 컴포넌트 안에서 날짜를 여러 개 선택하는 방식으로 바꿨습니다.

즉:

```text
텍스트 입력
-> 달력에서 날짜 여러 개 선택
```

구조가 됐습니다.

추가로:

- 월 이동 가능
- 지난 날짜 선택 불가
- 선택된 날짜를 칩으로 다시 확인 및 해제 가능

하도록 정리했습니다.

선택한 날짜가 하나도 없으면 등록 버튼이 비활성화됩니다.

## 2. 지원 조건 칩 UI 변경

기존에는 지원 조건도 긴 텍스트로 입력했습니다.

이번에는:

- 직접 입력 후 `추가`
- 추천 조건 칩 탭
- 선택된 조건 칩 삭제

가 가능한 구조로 바꿨습니다.

선택된 조건이 하나도 없으면 등록 버튼이 비활성화됩니다.

## 3. 위치 입력 구조 정리

사용자 요청처럼 위치는 한 가지 방식만으로는 부족할 수 있어서, 이번에는 구조를 먼저 나눴습니다.

- `상세 위치`: 실제 정확한 주소
- `상세 위치 공개 방식`

공개 방식은:

- `예약 후 상세 위치 안내`
- `처음부터 상세 위치 공개`

중 하나를 고르게 했습니다.

공개 위치 입력을 따로 받기보다, 상세 위치를 기준으로 공개용 위치를 파생시키는 방향으로 정리했습니다.

## 지도 API에 대해

질문하신 방향이 맞습니다.

나중에 검색과 정확한 탐색을 하려면 결국:

- 주소 입력
- 지도 API / 지오코딩
- 좌표 저장

이 필요합니다.

다만 이번 단계에서는 먼저 UI와 데이터 구조를 준비했고, 다음에 지도 API를 붙이면:

- 공개 위치는 검색용 지역명
- 상세 위치는 실제 주소
- 좌표는 검색/정렬용

으로 자연스럽게 확장할 수 있습니다.
