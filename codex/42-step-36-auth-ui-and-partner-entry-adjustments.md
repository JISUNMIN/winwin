# 42. Step 36 인증 UI와 파트너 진입 동선 조정

## 목표

Step 35에서 mock auth와 role guard를 붙인 뒤, 실제로 써보면서 화면 진입 방식과 버튼 의미를 더 자연스럽게 다듬습니다.

이번 단계에서는:

- 홈 상단에서 `게스트 / 고객 / 파트너` 역할을 바로 바꿀 수 있게 정리
- 권한 안내는 다시 `/auth` 페이지 방식으로 유지
- 파트너 전용 진입은 상세 화면이 아니라 메인 화면 쪽으로 이동
- 메인 카드의 `지원하기` 텍스트를 `상세보기`로 변경
- 파트너는 상세 화면에서 `지원하기`를 보지 않게 정리

까지 반영했습니다.

## 1. 웹 확인을 위해 홈에서 역할을 바로 바꾸게 함

웹에서는 `/auth` 이동 반응을 확인하기가 불안정해서, 홈 상단에 바로 역할 전환 버튼을 추가했습니다.

현재 홈 상단에는:

- `로그인`
- `게스트`
- `고객`
- `파트너`

버튼이 함께 보입니다.

여기서 `게스트 / 고객 / 파트너`는 라우팅 없이 상태를 즉시 바꿔서, 웹과 앱에서 현재 역할을 바로 시험해볼 수 있게 했습니다.

## 2. 권한 안내는 다시 `/auth` 페이지 유지

중간에 전역 overlay 방식도 시도했지만, 최종적으로는 원래 의도에 맞게 `/auth` 페이지로 다시 정리했습니다.

즉:

```text
권한 필요한 화면 진입
-> /auth 페이지 이동
-> 역할 선택
-> 원래 화면으로 복귀
```

구조는 유지하고, 홈에서는 테스트 편의를 위해 역할 버튼을 추가한 상태입니다.

## 3. 파트너 동선은 메인에서 여는 쪽으로 변경

처음에는 파트너가 매칭 상세 화면 안에서 `...` 메뉴로 `상담 목록 / 공고 관리`로 들어가게 했습니다.

하지만 이 방식은:

- 고객용 CTA와 파트너용 관리 동선이 상세 화면에서 섞이고
- `지원하기` 버튼 의미와도 충돌하고
- 파트너가 관리 기능을 찾기 어려울 수 있어서

최종적으로 메인 화면 쪽에 두는 방향으로 바꿨습니다.

## 4. 파트너 전용 진입은 메인 우측 상단의 작은 메뉴

큰 카드형 `파트너 바로가기`는 화면 위쪽을 많이 차지해서 제거했습니다.

대신 파트너 역할일 때만 홈 우측 상단에 작은 `파트너 바로가기` 버튼이 보이고,

- `상담 목록`
- `공고 관리`

두 메뉴가 열리도록 정리했습니다.

이번 경우에는:

- 햄버거 메뉴: 범위가 너무 큼
- `...`: 의미가 약함
- `파트너 바로가기`: 현재 역할과 목적이 가장 잘 보임

이라서 `파트너 바로가기`가 가장 적절하다고 판단했습니다.

## 5. 메인 카드 CTA는 `상세보기`

홈 목록 카드는 아직 상담을 시작하는 버튼이 아니라 상세 화면으로 들어가는 버튼입니다.

그래서 카드 하단 CTA 텍스트를:

```text
지원하기 -> 상세보기
```

로 바꿨습니다.

이제 사용자는 홈에서:

```text
상세보기
-> 상세 화면 진입
-> 고객이면 지원하기
```

흐름으로 이해할 수 있습니다.

## 6. 파트너는 상세 화면에서 지원하기 비노출

파트너 역할은 지원 대상이 아니라 관리 역할이므로, 상세 화면 하단 `지원하기` 바는 파트너에게 보이지 않게 유지했습니다.

즉:

- 고객/게스트: 상세 하단에 `지원하기`
- 파트너: `지원하기` 없음

으로 정리됐습니다.

## React 개발자 기준으로 보면

이번 단계는 권한 구조 자체를 새로 만든 것이 아니라, 이미 붙어 있는 auth 상태를 기준으로 화면 진입 CTA와 버튼 문구를 더 자연스럽게 리팩터링한 단계입니다.

웹 React 느낌으로 보면:

- 홈 상단 역할 버튼: 개발용 auth state 토글
- `/auth` 페이지 유지: 로그인이 필요한 순간 전용 진입 페이지
- `지원하기 -> 상세보기`: 실제 클릭 동작에 맞춘 CTA 카피 수정
- 파트너 바로가기 메뉴: 역할별 관리 메뉴를 상세 내부가 아니라 홈 헤더로 이동

처럼 이해하면 됩니다.

## 핵심 코드

```ts
onPress={() => signInAs('partner')}
```

홈에서 라우팅 없이 역할을 즉시 바꿔서, 웹에서도 상태 시험이 쉽게 되게 했습니다.

```ts
<Text style={styles.actionText}>{onPress ? '상세보기' : '상세 화면 다음 단계'}</Text>
```

홈 카드의 CTA 문구를 실제 동작과 맞게 조정했습니다.
