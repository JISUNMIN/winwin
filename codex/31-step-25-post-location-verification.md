# 31. Step 25 공고 등록 위치 확인과 좌표 저장

## 목표

공고 등록 화면의 위치 입력을 실제 검색/정렬 준비가 되는 수준으로 끌어올립니다.

이번 단계에서는:

- 상세 위치 주소 확인
- 현재 위치 불러오기
- 좌표 저장
- 상세 위치 기준 공개 위치 자동 생성

까지 연결했습니다.

## 1. 상세 위치 하나만 검증

이제 단순히 텍스트만 적는 것이 아니라:

- `상세 위치 확인`

버튼을 눌러 실제 주소를 확인할 수 있습니다.

`expo-location`의 geocoding / reverse geocoding을 이용해서 좌표를 만들고, 가능한 경우 더 정리된 주소 형태로 다시 보여줍니다.

## 2. 현재 위치 불러오기 추가

샵이 현재 매장 위치에서 바로 공고를 등록할 수 있도록 `현재 위치 불러오기` 버튼도 추가했습니다.

권한이 허용되면:

- 상세 위치
- 좌표

를 현재 위치 기준으로 한 번에 채우고, 공개용 위치도 자동으로 계산합니다.

## 3. 등록 조건 강화

이제 등록 버튼이 활성화되려면 아래 조건이 모두 필요합니다.

- 샵 이름 입력
- 서비스명 입력
- 상세 위치 입력 및 확인 완료
- 지원 조건 1개 이상
- 가능 날짜 1개 이상

즉, 위치도 이제 실제 확인된 상태여야 등록됩니다.

## 4. 데이터 구조에 좌표 추가

`src/data/matchings.ts`에 좌표 타입을 추가했습니다.

- `locationCoordinates`
- `locationDetailCoordinates`

이 값은 지금은 mock 메모리 저장에만 들어가지만, 다음에:

- 가까운 공고 정렬
- 지역 검색
- 지도 표시

를 붙일 때 바로 이어서 쓸 수 있습니다.

## 5. 위치 공개 방식과 실제 저장의 차이

이번 구조에서는:

- `상세 위치`: 내부적으로 저장되는 실제 주소
- `공개 방식`: 예약 후 안내 / 처음부터 공개

를 중심으로 저장합니다.

그리고 목록에 보일 공개 위치는 상세 위치에서 자동으로 만듭니다.

- `예약 후 안내`: `경기도 수원시 영통구`처럼 지역까지만 노출
- `처음부터 공개`: 상세 위치 전체를 그대로 노출

즉, 사용자에게는 지역만 먼저 보여주더라도 앱 내부에서는 정확한 좌표와 상세 주소를 같이 가지고 있을 수 있습니다.

## React 개발자 기준으로 보면

- 웹에서 주소 입력 후 geocoding API를 호출해 좌표를 받아오는 폼과 같은 개념입니다.
- 차이는 브라우저 geolocation API 대신 RN에서는 `expo-location`을 쓰고, 주소 확인/현재 위치 불러오기를 같은 컴포넌트 state 안에서 관리한다는 점입니다.
- 위치 문자열 하나만 저장하지 않고, 화면 표시용 텍스트와 좌표 데이터를 같이 관리하는 구조가 핵심입니다.

## 핵심 로직

- 상세 주소를 입력한 뒤 `상세 위치 확인`을 누르면 geocode와 reverse geocode를 순서대로 실행합니다.
- 성공하면 주소 문자열을 정리하고 `locationCoordinates`, `locationDetailCoordinates`를 함께 저장합니다.
- 공개 위치는 상세 주소에서 자동으로 파생해서, 노출용 텍스트와 내부 저장용 상세 주소를 분리합니다.

## 핵심 코드

```ts
const geocoded = await Location.geocodeAsync(query);
const coordinates = {
  latitude: geocoded[0].latitude,
  longitude: geocoded[0].longitude,
};
```

입력한 상세 주소를 좌표로 바꾸는 핵심 부분입니다. 이 좌표를 이후 검색/정렬용 데이터로도 쓸 수 있게 저장합니다.
