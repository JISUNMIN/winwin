# 18. Step 12 샵 일정 선택 흐름

## 목표

고객이 여러 개의 희망 일정을 보내면, 샵이 그중 하나를 직접 골라 예약 확정 요청을 보내는 흐름으로 바꿉니다.

이전 mock에서는 첫 번째 희망 일정을 자동으로 사용했습니다.

## 만든 파일

```text
src/components/winwin/ShopScheduleReviewCard.tsx
```

## 수정한 파일

```text
src/app/chat/[id].tsx
```

## 바뀐 흐름

이전 흐름:

```text
고객이 희망 일정 여러 개 전송
-> 샵이 첫 번째 일정을 자동 선택
-> 예약 확정 요청 카드 생성
```

현재 흐름:

```text
고객이 희망 일정 여러 개 전송
-> 샵 안내 메시지 생성
-> 샵 일정 선택 카드 생성
-> 카드에서 가능한 일정 하나 선택
-> 그 일정으로 예약 확정 요청 카드 생성
```

## 새 카드의 역할

`ShopScheduleReviewCard`는 샵이 여러 후보를 검토하는 중간 단계를 보여주는 카드입니다.

카드 안에는:

- 고객이 보낸 날짜/시간 후보 목록
- 각 후보의 `이 일정 선택` 버튼
- 이번 예약 요청에 들어갈 보증금 안내

가 들어 있습니다.

## 채팅 메시지 타입 확장

채팅 화면의 `Message` 타입에 아래 종류를 추가했습니다.

```ts
type Message = {
  type:
    | 'text'
    | 'image'
    | 'desired-schedule'
    | 'shop-schedule-review'
    | 'booking-request';
};
```

여기서 `shop-schedule-review`는 샵이 일정을 고르는 중간 UI를 의미합니다.

## 왜 이렇게 나눴는지

이전 방식은 빨리 동작을 확인하기에는 좋았지만, 실제 예약 조율 흐름과는 조금 달랐습니다.

이번처럼 중간 단계를 따로 두면 나중에:

- 샵 사장님 전용 화면 분리
- 가능한 일정만 선택
- 선택 사유 메시지 추가
- 예약 요청 전 수정

같은 확장도 훨씬 쉬워집니다.
