# 26. Step 20 상담 mock 동기화와 샵 목록 필터

## 목표

아래 3가지를 한 번에 정리합니다.

- 역할별 초기 mock 메시지와 상태를 더 현실적으로 분리
- 샵 상담 목록에 상태 필터 추가
- 목록 카드에 미확인 메시지 수와 최근 업데이트 시간 표시

## 만든 파일

```text
src/data/consultations.ts
```

## 수정한 파일

```text
src/components/winwin/ChatScreen.tsx
src/app/shop/index.tsx
```

## 1. 공용 상담 mock 데이터 분리

기존에는:

- 채팅 화면의 초기 메시지
- 샵 상담 목록의 상태 카드

가 서로 따로 놀았습니다.

이번에는 `src/data/consultations.ts`를 만들어서 둘이 같은 상담 mock 데이터를 같이 보도록 정리했습니다.

이 파일에는:

- 상담 상태
- 고객 이름 / 메모
- 미확인 메시지 수
- 최근 업데이트 시간
- 예약 흐름 상태
- 초기 채팅 메시지

가 함께 들어 있습니다.

## 2. 역할별 초기 상태를 더 현실적으로 분리

이제 상담마다 초기 채팅 상태가 다르게 시작합니다.

예를 들면:

- 어떤 상담은 `검토중`이라 희망 일정 카드가 이미 있음
- 어떤 상담은 `결제대기`라 예약 요청 카드가 이미 있음
- 어떤 상담은 `확정`이라 결제 완료 이후 메시지까지 있음
- 어떤 상담은 아직 `대기`라 기본 상담 단계임

즉, 고객/샵이 보는 채팅도 이제 공통 generic 상태가 아니라 상담별 흐름에 맞는 mock 상태로 시작합니다.

## 3. 샵 상담 목록 상태 필터 추가

`/shop` 화면에 아래 필터 버튼을 추가했습니다.

- `전체`
- `대기`
- `검토중`
- `결제대기`
- `확정`

샵은 이제 원하는 상태의 상담만 골라서 볼 수 있습니다.

## 4. 최근 업데이트 / 미확인 메시지 표시

상담 카드에 아래 정보도 추가했습니다.

- `최근 업데이트 20분 전`
- `미확인 2`

최근 업데이트 시간은 `updatedAt` 기준으로 계산해서 상대 시간처럼 보여줍니다.

## 왜 이 단계가 중요한지

이제 샵 목록과 채팅 화면이 같은 mock 상담 데이터를 공유하기 때문에:

- 목록 상태와 채팅 상태가 서로 맞고
- 역할별 흐름도 더 자연스럽고
- 이후 서버 데이터 구조를 붙일 때도 방향이 더 명확해집니다

## React 개발자 기준으로 보면

- 이 단계는 흩어져 있던 mock 상태를 하나의 데이터 파일로 모으는 작업입니다.
- 웹 React에서도 여러 페이지가 같은 임시 데이터를 따로 들고 있으면 어긋나기 쉬운데, `consultations.ts` 같은 shared module로 빼면 훨씬 안정적입니다.
- 상태 필터는 웹의 리스트 필터 버튼과 동일한 패턴이고, 선택된 필터에 따라 렌더링할 배열만 바뀝니다.

## 핵심 로직

- `src/data/consultations.ts`에 상담 상태, 메시지, unread 수, updatedAt을 한 곳에 모아뒀습니다.
- 샵 목록은 이 데이터를 필터링해서 보여주고, 채팅 화면도 같은 데이터를 초기 상태로 사용합니다.
- 그래서 한 상담이 `결제대기`인지 `확정`인지 같은 정보가 목록과 채팅에서 같은 기준으로 보이게 됩니다.

## 핵심 코드

```ts
const filteredConsultationItems = consultationItems.filter((item) =>
  selectedFilter === 'all' ? true : item.statusTone === selectedFilter,
);
```

선택된 필터 값에 따라 목록에서 보여줄 상담만 골라냅니다.
